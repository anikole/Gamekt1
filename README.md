Это текстовая игра квест, отображающаяся в терминале символами ASCII. 
В этой игре есть 5 локаций, различные головоломки, сундуки с наградами (в псоледнем особая награда за прохождение игры).

---

## 🚀 Особенности проекта

*  **Динамический мир**: Исследование локаций и взаимодействие с окружением (двери, сундуки).
*  **Головоломки (BrainBreaker)**: Интегрированная система текстовых загадок и мини-игр.
*  **Кроссплатформенность**: Проект легко собирается и работает как на Windows, так и на Linux благодаря универсальному Makefile.

---

## 🛠️ Сборка и запуск

Проект собирается с помощью утилиты `Make` и компилятора `g++` (с поддержкой стандарта C++17).

### 1. Сборка проекта
Откройте терминал в корневой папке проекта и выполните команду:

* **В Windows (через MinGW):**
  ```bash
  mingw32-make
  ```
* **В Linux :**
  ```bash
  make
  ```

### 2. Запуск игры
* **В Windows:** `my_program.exe`
* **В Linux:** `./my_program`

### 3. Очистка временных файлов
Если нужно удалить объектные файлы (`.o`, `.d`) и исполняемый файл:
```bash
make clean        # Для Linux
mingw32-make clean # Для Windows
```

## 🕹️ Как играть (Управление)

Игра управляется через консоль с помощью ввода текстовых команд или цифр. 
* Выбор действий в меню: введите `INV` для открытия инвентаря и нажмите **Enter**.
* Перемещение: команды направления : UP(или U), DOWN(или D), LEFT(или L), RIGHT(или R).

## 🏗️ Архитектура и Классы

Проект построен на объектно-ориентированном подходе (ООП):

* **`game`** — Главный цикл игры, обработка ввода и игровая логика.



### 👤 Класс `Character`
Описывает игрового персонажа, его характеристики, инвентарь и логику перемещения по сетке карты размером **11 × 7** (координаты `(0,0)` находятся в левом верхнем углу).

#### Поля класса:
* `Character_x`, `Character_y` — Текущие координаты персонажа на карте.
* `Character_health` — Уровень здоровья (максимум — 100 единиц).
* `Character_live` — Статус жизни: `1` (жив) или `0` (мертв).
* `inventory` — Динамический массив (вектор) предметов персонажа.

#### Методы перемещения:
Каждый метод принимает количество шагов и возвращает обновленную координату. Если персонаж пытается выйти за границы карты, выводится сообщение: *«Вы врезались в стену карты»*.

* **`MoveUp(steps)`** — Перемещение вверх. Уменьшает `y`. Ограничение: `y - steps > 0`.
* **`MoveDown(steps)`** — Перемещение вниз. Увеличивает `y`. Ограничение: `y + steps < 7`.
* **`MoveLeft(steps)`** — Перемещение влево. Уменьшает `x`. Ограничение: `x - steps > 0` *(исправлено логическое условие разности)*.
* **`MoveRight(steps)`** — Перемещение вправо. Увеличивает `x`. Ограничение: `x + steps < 11`.

### 🗺️ Класс `Location`
Отвечает за представление игровой зоны (комнаты), хранение структуры карты и отрисовку объектов на ней.

#### Поля класса:
* `ID_Location` — Уникальный идентификатор локации.
* `Form` — Двумерный массив (сетка), используемый для отрисовки карты и объектов.

#### Символы отображения на карте:
* `#` — Стена (границы локации)
* `.` — Пол (свободное пространство)
* `@` — Персонаж игрока
* `C` — Сундук (`Chest`)
* `D` — Дверь (`Door`)

#### Методы класса:
* **`PrintForm(Character_x, Character_y  Chests_x, Chests_y, Door_x, Door_y)`**  
  Принимает текущие координаты персонажа, сундуков и дверей. С помощью циклов динамически заполняет двумерный массив `Form` стенами по краям, полом внутри и расставляет поверх маркеры объектов (`@`, `C`, `D`). Выводит финальную карту в терминал.

---

### 🎒 Класс `Inventory`
Управляет сумкой персонажа, отвечает за добавление, просмотр и использование предметов (зелий).

#### Поля класса:
* `items` — Динамический массив (вектор), хранящий объекты доступных зелий (`Potions`).

#### Методы класса:
* **`add_potion(potion)`**  
  Принимает объект зелья и добавляет его в массив инвентаря. Возвращает обновленный инвентарь.
  
* **`check_inventory()`**  
  Проверяет содержимое сумки. Если инвентарь пуст, выводит сообщение об этом. Если предметы есть, запускает цикл и выводит весь список в терминал. Возвращает инвентарь.
  
* **`use_potion(choice, character)`**  
  Принимает порядковый номер предмета (выбор игрока) и ссылку на персонажа.  
  * Корректирует индекс под массив (`index = choice - 1`).  
  * Проверяет существование предмета по индексу. Если индекса нет — сообщает, что зелье не существует.  
  * При использовании обычного зелья восстанавливает здоровье персонажу. Если итоговое HP превышает 100, оно автоматически урезается до лимита в **100 единиц**.  
  * При попытке использовать уникальный победный трофей выводит специальное сюжетное сообщение.  
  * Возвращает итоговое количество здоровья персонажа.

### 🧪 Класс `Potions`
Отвечает за создание предметов-зелий, генерируя их характеристики и названия случайным образом при инициализации объекта.

#### Поля класса:
* `Potions_ID` — Уникальный номер (идентификатор) зелья.
* `health_add` — Количество единиц здоровья, которое восстанавливает данное зелье.
* `Potion_Name` — Статический массив доступных наименований зелий.
* `last_treasure` — Флаг (значение финальной награды), определяющий, является ли предмет обычным зельем или победным трофеем.

#### Логика работы (Конструктор):
При создании нового зелья срабатывает встроенный генератор случайных чисел, который:
1. Присваивает случайный `Potions_ID`.
2. Случайным образом выбирает текстовое название из массива `Potion_Name`.
3. Задает случайное количество восстанавливаемого здоровья (`health_add`).

### 📦 Класс `Chests`
Управляет сундуками на локации: отвечает за их безопасное появление на карте, хранение наград и обработку взаимодействия с игроком.

#### Поля класса:
* `Chests_x`, `Chests_y` — Координаты сундука на карте.
* `Chests_ID` — Уникальный номер сундука (от 1 до 100).
* `Chests_reward` — Массив возможных наград, содержащихся в сундуке.
* `is_open` — Статус сундука: `true` (открыт) или `false` (заперт).
* `can_take_reward` — Флаг наличия награды внутри сундука.

#### 🎲 Логика генерации (Спавн сундука):
При создании сундука запускается алгоритм безопасного размещения на карте:
1. **Генерация ID**: Случайно выбирается число от 1 до 100.
2. **Бросок монетки (0 или 1)**: В зависимости от результата сундук генерируется в разных диапазонах координат. Диапазон привязан к стартовой позиции игрока, чтобы сундук **не мог появиться прямо на игроке**.
3. **Проверка коллизии с дверью**: Если сгенерированные координаты совпали с координатами двери, координаты сундука автоматически перезаписываются.

#### Методы класса:
* **`check_Collision(character, command, inventory, location_count)`**  
  Проверяет, наступил ли игрок на сундук, и обрабатывает логику получения награды:
  * Если координаты совпали, проверяется «бросок монетки». Если выпал `0` — сундук пуст, выводится сообщение.
  * Если награда есть (`1`), проверяется статус `is_open`. Если сундук уже был открыт — игрок просто забирает содержимое.
  * Если сундук заперт — запускается головоломка. При правильном решении сундук открывается, награда падает в `inventory`. При ошибке — у игрока снижается здоровье.
  * **Специальное условие (Финал)**: Если счетчик локаций равен `5`, в сундук помещается *особая награда*. При её взятии выводится сообщение об успешном прохождении всей игры.
  * Возвращает обновленный инвентарь игрока.

### 🚪 Класс `Door`
Отвечает за переходы между игровыми локациями, генерацию дверей на карте и защиту переходов с помощью головоломок.

#### Поля класса:
* `Door_x`, `Door_y` — Координаты двери на карте.
* `location_count` — Счетчик текущей локации (уровня).
* `is_open` — Статус двери: `true` (открыта) или `false` (заперта).

#### 🎲 Логика генерации (Спавн двери):
Координаты двери генерируются случайным образом с использованием алгоритма «монетки» (аналогично классу `Chests`). Это гарантирует, что дверь не появится на стартовой позиции игрока и не застрянет в текстурах стен.

#### Методы класса:
* **`check_collision_door(character, command)`**  
  Проверяет, подошел ли игрок к двери, и управляет процессом перехода на следующий уровень:
  * Если координаты игрока и двери совпадают, программа запрашивает подтверждение перехода.
  * Если игрок отказывается переходить, выводится соответствующее текстовое сообщение.
  * Если игрок соглашается, запускается сюжетная головоломка.
  * **При правильном ответе**: Дверь открывается (`is_open = true`), счетчик локаций увеличивается, метод возвращает `true`.
  * **При неверном ответе**: Дверь остается запертой, у персонажа снижается уровень здоровья, метод возвращает `false`.

### 🧩 Класс `BrainBreaker`
Отвечает за генерацию и проведение текстовых головоломок и мини-игр, которые требуются для открытия сундуков или дверей.

#### Поля класса:
* `type_of_bb` — Тип текущей головоломки.
* `random_generator` — Рандомайзер, с помощью которого случайным образом определяется тип игры.

#### 💀 Важное системное правило:
Все методы мини-игр принимают прямую ссылку на объект `Character`. Если в процессе решения игрок ошибается, у него снижается здоровье. Если уровень здоровья падает до **`0` или ниже**, на экран выводится сообщение о гибели персонажа, и игра немедленно завершается.

---

#### 📦 Блок 1: Испытания для сундуков
* **`start_bb_for_chests(character)`**  
  Главный диспетчер мини-игр для сундуков. Запускает одну из трех головоломок в зависимости от значения `type_of_bb`. Возвращает `true` при успехе, `false` при неудаче или неизвестном типе игры.
* **`answer_math_quiz(character)`**  
  Математический тест. Игрок должен ввести сумму двух случайных чисел.
* **`play_riddle(character)`**  
  Текстовые загадки. Игрок должен ввести текстовое слово-отгадку к случайной загадке.
* **`guess_number(character)`**  
  Угадай число. Классическая игра, где нужно отгадать число за **3 попытки** с подсказками «больше/меньше».

---

#### 🚪 Блок 2: Испытания для дверей
* **`start_bb_for_door(character)`**  
  Главный диспетчер мини-игр для дверей. Работает аналогично диспетчеру сундуков, координируя логику прохода на следующую локацию. Возвращает `true` при успехе, `false` во всех остальных случаях.
* **`d_answer_math_quiz(character)`**  
  Математический тест для открытия двери. Игрок вводит сумму двух сгенерированных чисел. При ошибке дверь остается запертой, а здоровье падает.
* **`d_play_riddle(character)`**  
  Текстовые загадки для дверей. Случайная текстовая загадка, неверный ответ на которую блокирует проход и наносит урон.
* **`d_guess_number(character)`**  
  Угадай число для дверей. Мини-игра на **3 попытки** для разблокировки сюжетной двери.
